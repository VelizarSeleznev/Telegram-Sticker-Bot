# Media pipeline

## Telegram invariants

Перед отправкой бот проверяет итоговый video sticker:

- WebM с кодеком VP9;
- одна сторона ровно `512 px`, вторая не больше `512 px`;
- не больше `30 FPS`;
- без аудиодорожки;
- не больше `256 КБ`;
- стандартная длительность не больше `3 секунд`.

Static stickers масштабируются так, чтобы длинная сторона занимала `512 px`,
центрируются на прозрачном холсте `512x512` и сохраняются в WebP размером не
больше `512 КБ`. Маленькие импортированные WebP также увеличиваются, а не
остаются миниатюрой в центре холста.

## Video encoding

Бот не уменьшает тяжелые video stickers до невалидных `448x448` или `384x384`.
Он кодирует VP9 в два прохода и до четырех раз корректирует целевой битрейт по
фактическому размеру результата. После кодирования `ffprobe` проверяет все
инварианты до вызова Telegram API.

## Experimental 6 seconds

Пользователь может один раз включить постоянную настройку `/video6 on`.
Следующие видео кодируются с кадрами длительностью до 6 секунд, после чего поле
WebM Duration подменяется на короткое значение. `/video6 off` возвращает
стандартные 3 секунды.

Это обход официального ограничения Telegram, а не гарантированная возможность
Bot API. Он может перестать приниматься или воспроизводиться корректно после
изменений Telegram, поэтому стандартный режим остается значением по умолчанию.

## Design provenance

Итеративный подбор битрейта и идея experimental Duration patch изучены по
[grozovsky/StickerStudio](https://github.com/grozovsky/StickerStudio). На момент
проверки в репозитории не было корневого файла лицензии, поэтому исходный C# код
не копировался: реализация написана отдельно для Python pipeline этого бота.

Технические ограничения сверяются с официальной документацией:

- <https://core.telegram.org/stickers>
- <https://core.telegram.org/stickers/webm-vp9-encoding>
